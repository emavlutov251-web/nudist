# 🍃 Нудист

Мессенджер, которому нечего скрывать. Telegram + Discord в одном окне: чаты, группы, каналы, серверы с ролями, голосовые комнаты, звонки, боты, истории — и кнопка «Прикрыться» на случай начальника.

## Запуск

```bash
cd nudist
npm start            # то же, что node server/boot.js
```

Откройте `http://localhost:3000`. Нужен только Node.js 18+ — зависимостей и сборки нет, `npm install` не требуется.

**Первый зарегистрированный человек становится суперадмином.** Админка — по адресу `/admin`. Назначать и снимать администраторов можно прямо в приложении: Настройки → «Администраторы» или профиль человека → «Ещё» → «Роль администратора». Это доступно главному админу; менять роль другого главного админа может только владелец из `OWNERS`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `3000` | порт HTTP и WebSocket |
| `DATA_DIR` | `./data` | база `db.json` и загруженные файлы |
| `HOST` | `0.0.0.0` | на каком адресе слушать; за обратным прокси — `127.0.0.1` |
| `TURN_HOST`, `TURN_SECRET` | — | свой coturn (`use-auth-secret`): сервер выдаёт клиентам пароль на 12 часов. `TURN_PORT` — порт, по умолчанию 3478 |
| `ICE_SERVERS` | публичный STUN | готовый JSON со STUN/TURN, если `TURN_HOST` не задан |
| `OWNERS` | — | id аккаунтов владельцев сервиса через запятую: при старте они получают роль главного админа, снять её нельзя |
| `SUPABASE_URL`, `SUPABASE_KEY` | — | облачное хранилище для хостингов без постоянного диска (см. ниже). `SUPABASE_BUCKET` — имя бакета, по умолчанию `nudist` |
| `MAX_UPLOAD_MB` | `100` | лимит файла (у Премиума ×4) |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_KEY_ID`, `S3_SECRET` | — | S3-хранилище для файлов (музыка, клипы, вложения), см. «Больше места под файлы». `S3_REGION` (по умолчанию `ru-central-1`), `S3_PREFIX` (`uploads`), `S3_MAX_GB` (`14`) — свой потолок объёма |
| `CACHE_MB` | `700` | сколько файлов держать на локальном диске, когда они хранятся в облаке |
| `LEAF_TAPS` | `10` | сколько тапов в «Листопаде» дают один листик |
| `LEAF_DAY_LIMIT` | `150` | сколько листиков в день можно натапать |
| `LEAF_DAILY_MIN`, `LEAF_DAILY_MAX` | `10`, `20` | размер ежедневного бонуса |
| `LEAF_SHARE_AGE_H` | `24` | через сколько часов после регистрации можно делиться листиками (`0` — сразу) |
| `LEAF_SHARE_MAX` | `100000` | сколько листиков можно передать за один раз |
| `LEAF_START` | `500` | сколько листиков у нового аккаунта |
| `MAINT` | — | разовые работы по базе: `<метка>:unmute,stars=500` — снять все муты и выставить всем людям ровно 500 листиков; каждая метка выполняется один раз |
| `MUSIC_MAX_TRACKS` | `300` | сколько треков помещается в одну библиотеку |
| `LIVE_MAX_VIEWERS` | `30` | зрителей на один прямой эфир |
| `ALLOW_PRIVATE_FETCH` | — | разрешить превью ссылок и RSS из локальной сети |

Звонкам, микрофону и шифрованию браузер требует HTTPS или `localhost`.

## Что попробовать за пять минут

1. Зарегистрируйтесь, откройте второе окно в режиме инкогнито и заведите второго человека.
2. Найдите друг друга через поиск (Ctrl+K), напишите `||секрет||` — спойлер прикроется фиговым листком.
3. Наберите `/` — кубик, монетка, шар судьбы, `/shrug`. `/buzz` трясёт окно собеседника.
4. Скрепка → «Мемогенератор». В любом чате: `@membot кот`.
5. Слева — сервер «Общий пляж»: каналы, форум, голосовая «Курилка» (вход одним кликом, рация на пробеле).
6. Меню ☰ → «Секретный чат»: сквозное шифрование, ключи только в двух браузерах.
7. Меню ☰ → «Листики и Премиум» → игра «Листопад». Листики тратятся на Премиум и бусты.
8. Дважды Esc — и на экране квартальный отчёт. Ещё дважды — обратно.
9. ↑ ↑ ↓ ↓ ← → ← → B A — секретная тема «Загар».

## Что внутри

```
server/            Node.js без зависимостей (ws лежит в server/vendor)
  index.js         HTTP, статика, загрузки, WebSocket RPC, таймеры
  core.js          база (JSON-файл), права, сообщения
  auth.js          пароли (scrypt), TOTP, сессии, QR-вход
  rpc.js           аккаунт, чаты, группы, каналы, сообщения, поиск, истории, листики
  guild.js         серверы, роли, вебхуки, события, голосовые комнаты, сигналинг звонков
  bots.js          встроенные боты, HTTP Bot API, inline-режим, Mini Apps, RSS
  admin.js         админка: RBAC, статистика, мониторинг, журнал, API-ключи
  net.js           безопасные исходящие запросы (защита от SSRF), превью ссылок
  seed.js          стартовый контент
public/            клиент без сборки: Preact + htm, свои шрифты и иконки
  js/              app, sidebar, chat, composer, media, panels, guildui, rtc, settings, fun…
  admin.html       «Вышка спасателя» — отдельное приложение владельца сервиса
  miniapps/        мини-приложения: «Листопад», «2048», «Сапёр», «Жребий», «Скинемся» и общий kit.js
```

Протокол: WebSocket `/ws?token=…`, запрос `{id, m, p}` → ответ `{id, r}` либо `{id, e}`, события `{ev, d}`.

### Bot API

Бота выдаёт `@botbatya` (`/newbot`). Дальше — как в Telegram:

```bash
curl http://localhost:3000/bot<ТОКЕН>/getMe
curl "http://localhost:3000/bot<ТОКЕН>/getUpdates?timeout=25"
curl -H 'Content-Type: application/json' \
  -d '{"chat_id":"<ID>","text":"Привет, голые люди!"}' \
  http://localhost:3000/bot<ТОКЕН>/sendMessage
```

Вебхуки серверов: `POST /hook/<id>/<token>` с телом `{"content":"…"}` или в формате Slack `{"text":"…","username":"…"}`.

### Mini Apps

**Каталог.** «Скрепка» в поле ввода → «Приложения» (а также вкладка «Приложения» и пункт в меню ☰). Приложение открывается поверх чата; результат оно может отправить в этот чат — только после подтверждения пользователя. Встроенные: «Листопад», «2048», «Сапёр», «Жребий», «Скинемся». Боты с Mini App попадают в раздел «От ботов», когда администратор включил им «бот в каталоге» (свои боты владелец видит сразу).

Свое приложение без бота — это страница в `public/miniapps/` (скрипты только внешними файлами, встроенные запрещает CSP) плюс строка в `APPS` в `server/hub.js`. Общение с мессенджером — модуль `/miniapps/kit.js`: `ready(fn)` (в ответ придут имя пользователя и тема), `share(text)` (отправить в чат), `close()`.

Мини-приложение бота открывается во фрейме, получает `#tgWebAppData=<подписанные данные>` и общается с мессенджером через `postMessage`: шлёт `{nudist:'ready'|'tap'|'daily'}`, получает `{nudist:'balance'|'bonus'|'error'}`. Пример — `public/miniapps/listopad.js`.

### Админка

Роли: Наблюдатель → Модератор → Админ → Суперадмин. Разделы: сводка (DAU/WAU/MAU), пользователи (бан, мут, разлогин, бейджи, премиум, листики), очередь жалоб, сообщества (верификация, удаление), мониторинг, фича-флаги, объявление всем, журнал действий, API-ключи.

Интеграционный API: `GET /api/admin/{stats,monitor,flags}` с заголовком `Authorization: Bearer nud_…`.

## Свой сервер в интернете (VPS)

Чтобы переписываться из разных городов, сервер должен стоять на машине с постоянным адресом в интернете. Нужен VPS с Debian 12/13 или Ubuntu 22.04/24.04 и, желательно, свой домен, A-запись которого указывает на этот VPS.

```bash
# на своём компьютере: залить архив на сервер
scp nudist-server.zip root@АДРЕС_СЕРВЕРА:/root/
# на сервере
apt-get update && apt-get install -y unzip
cd /root && unzip -o nudist-server.zip && sudo bash nudist/deploy/install.sh nudist.example.ru
```

Без домена (`sudo bash nudist/deploy/install.sh`) скрипт возьмёт бесплатный адрес вида `203-0-113-7.sslip.io`; сертификат для такого адреса выдаётся не всегда.

Что настраивает `deploy/install.sh`:

- **Служба `nudist`** под отдельным пользователем: стартует при загрузке, перезапускается через 2 секунды после падения.
- **Сторож**: раз в минуту спрашивает `/api/health`; два неответа подряд — перезапуск (на случай зависания).
- **https**: Caddy сам получает и продлевает сертификат. Без https не работают микрофон, камера, звонки и секретные чаты.
- **TURN (coturn)**: без него звонки между мобильными сетями часто не соединяются. Пароли временные, выдаёт сервер.
- **Копии**: база и файлы раз в сутки в `/var/backups/nudist`, хранится 14 штук. Плюс рядом с базой лежит `db.json.bak`: если основной файл окажется битым, сервер поднимется с копии.
- **Порты** у хостера должны быть открыты: 80, 443, 3478 (tcp и udp), 49160–49400 udp.

Повторный запуск скрипта обновляет код; данные, домен и ключ TURN сохраняются. Свои переменные дописывайте в `/etc/nudist.env` ниже строки «свои настройки».

Проверено в песочнице: скрипт проходит от начала до конца, сервер стартует под служебным пользователем, конфигурации Caddy и systemd проходят проверку, coturn принимает пароли сервера и отклоняет чужие, база переживает `kill -9` и восстанавливается из копии. Не проверено: выдача сертификата на настоящем домене, работа под настоящим systemd, звонок между двумя мобильными сетями, нагрузка.

Запас по нагрузке: один процесс и база в одном JSON-файле. Этого хватает компании друзей или небольшому сообществу; на тысячи одновременных пользователей архитектура не рассчитана.

## Docker: тот же сервер в контейнере

Образ собирается из `Dockerfile` (Node 20 на Alpine, около 140 МБ, работает не от root). База и файлы лежат в томе `/data`.

```bash
# только мессенджер, без https — для пробы на своём компьютере: http://localhost:3000
docker build -t nudist .
docker run -d --name nudist -p 3000:3000 -v nudist-data:/data nudist

# полный сервер на VPS: мессенджер + https (Caddy) + TURN для звонков (coturn)
cp .env.example .env        # вписать DOMAIN, PUBLIC_IP, TURN_SECRET
docker compose up -d
docker compose logs -f app
```

Остальные настройки (`OWNERS`, `S3_*`, `MAX_UPLOAD_MB` и прочие из таблицы выше) дописываются в `.env`. Порты у хостера те же, что для `install.sh`: 80, 443, 3478 (tcp и udp), 49160–49400 udp.

Копия данных: `docker run --rm -v nudist_nudist-data:/data -v "$PWD":/backup alpine tar czf /backup/nudist-$(date +%F).tar.gz -C /data .`

Docker и `deploy/install.sh` — два равноценных способа, выбирайте один. PostgreSQL и Redis в `docker-compose.yml` нет: мессенджер ими не пользуется (см. «Сколько людей выдержит»).

Проверено в песочнице: образ собирается, контейнер отвечает и проходит проверку здоровья, после пересоздания контейнера аккаунт и файл на месте; `docker compose up` поднимает все три службы, сайт открывается по https через Caddy, WebSocket проходит, coturn принимает временный пароль сервера и отвергает неверный. На настоящем VPS с настоящим сертификатом связка не запускалась.

## Чтобы жило годами: две копии базы и самовосстановление

База целиком хранится в двух независимых местах, если заданы и Supabase, и S3:

- **Supabase** — основное: снимок пишется через несколько секунд после каждого изменения, плюс копия на каждый день месяца. Раз в шесть часов сервер сам обращается к проекту, чтобы тот не считался заброшенным.
- **S3** — вторая копия: `db/main.gz` обновляется раз в две минуты и при остановке сервера; `db/main-ГГГГ-ММ-ДД.gz` — копия на каждый день (хранится 35 дней, копии за первое число каждого месяца остаются навсегда).

При запуске сервер читает обе копии и берёт более свежую. Если Supabase не отвечает (проект приостановили, удалили, сменили ключ), сервер поднимается из копии в S3 и продолжает работать на ней, обновляя её каждые 45 секунд; когда Supabase вернётся, он получит актуальное состояние. Сервер отказывается запускаться, только если базу взять совсем неоткуда: стартовать с пустой и затереть ею настоящую нельзя. На своём сервере без Supabase копия в S3 работает как резервная вне диска: на новой пустой машине база поднимется из неё сама.

Состояние видно в `/api/health`: `cloud` — Supabase, `mirror` — копия в S3 (`primary: true` значит, что сервер сейчас живёт на копии). Отключить вторую копию: `DB_MIRROR=off`.

Откатиться на копию за нужный день: остановить сервер, скачать `db/main-ГГГГ-ММ-ДД.gz` из бакета, распаковать в `data/db.json` (на Render — записать его в строку `main` таблицы `nudist_state`, сжав gzip и закодировав base64) и запустить снова.

Чего это не закрывает: бесплатные тарифы Render, Supabase и хранилища могут изменить условия; ключ S3 имеет срок действия; домен `onrender.com` в России открывается не у всех. Надёжнее всего свой платный сервер (раздел про VPS) с этой же копией в S3.

## Подарки и листики

- **Поделиться листиками** — перевод другому человеку с подписью (`stars.send`), история переводов (`stars.history`).
- **Подарки** (`server/gifts.js`, `public/js/gifts.js`) — 16 подарков от 10 до 250 🍃. Подарок приходит карточкой в личный чат и остаётся в профиле получателя. Хозяин может спрятать его из профиля или продать за 80% цены. Имя дарителя можно скрыть от посторонних.
- **Где это в интерфейсе:** в личном чате кнопка 🎁 стоит рядом со скрепкой; в профиле у каждого человека есть вкладка «Подарки» со счётчиком, её видят все (спрятанные подарки — только хозяин).
- Дарить и делиться можно через 24 часа после регистрации (`LEAF_SHARE_AGE_H`), не чаще 12 раз в минуту. На администраторов срок не действует.

## Политика конфиденциальности

- Текст — `public/privacy.html`, открывается по адресу `/privacy`. В нём перечислено, что хранит сервис, кто это видит, где лежат данные и как их удалить. Поменяли хостинг или набор данных — поправьте текст.
- Редакция задаётся константой `POLICY` в `server/core.js` (дата). Сменили дату — приложение при следующем входе попросит каждого принять политику заново.
- При регистрации стоит обязательная галочка. У кого согласия с действующей редакцией нет (старые аккаунты, вход по номеру), тот видит экран с кратким изложением и кнопками «Принимаю» и «Выйти»; дальше приложение не пускает. Согласие хранится в `user.policy = { v, ts }`, записывается методом `me.policy`.
- Год рождения другим пользователям не отдаётся: в чужом профиле сервер присылает только день и месяц.

## Мут, бан и права создателя

- **Группа или канал**: создатель и админы с правом «бан» могут запретить участнику писать на 1 час, сутки, неделю или бессрочно (`chat.mute`), исключить, забанить и разбанить. Мут хранится в самом чате: выйти и зайти заново, чтобы его сбросить, не получится. В канале мут закрывает комментарии.
- **Сервер**: заглушить, выгнать, забанить и разбанить — в настройках сервера, вкладка «Участники».
- **Админка** (`/admin`): мут на 1 час, сутки, неделю или месяц, бан и разбан. Мут от администрации закрывает сообщения, ленту, комментарии, клипы, истории и эфиры; «Избранное» и поддержка остаются доступны. Владелец сервиса (`OWNERS`) может управлять любым аккаунтом, кроме другого владельца.
- **К себе меры не применяются.** Сервер отказывает, если кто-то пытается замутить, забанить, разлогинить, заглушить, выгнать или заблокировать самого себя — в админке, группе, на сервере и в голосовой комнате. В админке на своей карточке этих кнопок нет.

## Защита и уборка файлов

- **Файлы стираются вместе с тем, к чему были приложены.** Удалили сообщение, переписку, группу, канал сервера, запись ленты, клип, трек, историю, аватар или аккаунт — через минуту сервер сверяется со всей базой и стирает файлы, на которые не осталось ни одной ссылки. Пересланное сообщение или то же фото в ленте файл удерживают. «Удалить у себя» файл не трогает. В секретных чатах приложение отдельно называет серверу адреса зашифрованных файлов (поле `files`), иначе сервер не знал бы, что стирать; секретные сообщения, отправленные до этого обновления, свои файлы за собой не убирают.
- **Сеансы хранятся под хешем.** В базе лежит SHA-256 от токена, сам токен есть только на устройстве. Старая база переводится сама при первом запуске, выходить и входить заново не нужно. Токены ботов и вебхуков остаются открытыми: их нужно показывать владельцу повторно, и ими подписываются данные мини-приложений.
- **Ограничение на загрузки:** `UPLOADS_PER_HOUR` (по умолчанию 200 файлов в час с аккаунта) и `UPLOAD_MB_PER_HOUR` (1024 МБ в час, с Премиумом втрое больше); с одного адреса — втрое больше, чем с аккаунта. Владельца и аккаунтов из `IMPORTERS` это не касается.
- **Адрес клиента.** Заголовку `X-Forwarded-For` сервер верит, только когда запрос пришёл от своего прокси (с локального или внутреннего адреса), и берёт из него последний адрес — тот, что дописал прокси. `TRUST_PROXY=off` — не верить заголовкам совсем; `TRUST_PROXY=2` — перед сервером два прокси; `TRUST_PROXY=cloudflare` — брать адрес из заголовка Cloudflare. С Caddy из `deploy/install.sh` и из `docker-compose.yml` настраивать ничего не нужно.
- **Секретные чаты.** Если ключ собеседника сменился (другое устройство, переустановка) или чат создан на другом вашем устройстве, в чате появляется предупреждение и кнопка «Новый секретный чат».

## Автоматическая проверка, выкладка и сторож (GitHub Actions)

- **`.github/workflows/deploy.yml`** — на каждый push в `main`, который меняет код: проверка синтаксиса, `node scripts/smoke.js` (регистрация, вход, WebSocket, загрузка файла на временной базе), сборка и запуск Docker-образа. Если всё прошло — выкладка на Render и проверка, что сайт отвечает. Сломанный код на сайт не попадает.
- **`.github/workflows/monitor.yml`** — раз в 15 минут спрашивает `/api/health`; если сайт молчит несколько минут, запуск падает и GitHub присылает письмо владельцу репозитория. Заодно проверяет, что данные сохраняются хотя бы в одно из двух хранилищ, и раз в сутки продлевает собственное расписание (GitHub отключает расписания в репозиториях без изменений за 60 дней). С 02:00 до 06:00 по Москве не проверяет: бесплатный Render в это время спит.

Настройки лежат в репозитории (Settings → Secrets and variables → Actions): секрет `RENDER_API_KEY`, переменные `RENDER_SERVICE_ID` и `SITE_URL`. При переезде на другой сервер достаточно поменять `SITE_URL`; без `RENDER_API_KEY` выкладка просто пропускается, проверки остаются. GitHub отключает расписание, если в репозитории 60 дней не было изменений, — тогда его включают заново на вкладке Actions.

## Бесплатный хостинг: Render + Supabase

На бесплатном тарифе Render диск стирается при каждом засыпании и перезапуске. Поэтому база и файлы хранятся в Supabase, а диск Render служит кешем.

Чтобы сервис не засыпал, сервер каждые 5 минут запрашивает собственный адрес (`RENDER_EXTERNAL_URL` или `KEEP_AWAKE_URL`). С 02:00 до 06:00 по Москве, если никого нет в сети, он себя не будит — так бесплатных 750 часов в месяц хватает с запасом. `KEEP_AWAKE=always` убирает ночную паузу, `KEEP_AWAKE=off` выключает самопрозвон.

**Старые телефоны.** `public/js/boot.js` — обычный скрипт, который грузится раньше приложения. Он добавляет недостающие функции старым Android System WebView и браузерам (`structuredClone`, `Array.at` и другие), переписывает современный CSS (`color-mix`, `dvh`, `inset`, `gap`) в понятный им вид и вместо вечной заставки показывает причину сбоя с кнопкой «Повторить». Проверено на Chromium 72, 74, 80 и 86. О сбоях запуска телефон сообщает серверу, в журнале это строки `[client]`.

**Россия без VPN.** Render отдаёт сайты через Cloudflare, а российские операторы обрывают такие соединения после первых 16 КБ. Настройками это не лечится: нужен хостинг не за Cloudflare, например российский VPS (раздел выше).

1. В Supabase создать проект и один раз выполнить SQL:
   ```sql
   create table if not exists public.nudist_state (id text primary key, data text not null, updated_at timestamptz not null default now());
   alter table public.nudist_state enable row level security;
   revoke all on public.nudist_state from anon, authenticated;
   ```
2. В Render создать Web Service из репозитория: build `npm install`, start `npm start`, health check `/api/health`.
3. Задать переменные: `SUPABASE_URL` (адрес проекта), `SUPABASE_KEY` (ключ `service_role`, его нельзя никому показывать), `NODE_VERSION=20`, `MAX_UPLOAD_MB=45` (в бесплатном Supabase файл не больше 50 МБ).

Как это работает: при старте сервер скачивает снимок базы из таблицы `nudist_state`; после каждого изменения отправляет новый снимок, не чаще раза в 4 секунды, и ещё раз при остановке. Раз в день при старте сохраняется копия (`main-day-NN`). Файлы уходят в бакет Storage и подтягиваются обратно по первому обращению. Если Supabase недоступен при старте, сервер не запускается вовсе, чтобы не затереть настоящую базу пустой.

Ограничения бесплатного варианта:

- Render усыпляет сервис через 15 минут без обращений; первое открытие после этого занимает до минуты.
- При жёстком падении теряется до 4 секунд последних изменений; при выкладке новой версии — то, что написано за время переключения.
- Supabase ставит бесплатный проект на паузу после недели без обращений; его нужно разбудить в панели Supabase, данные сохраняются.
- TURN-сервер на Render запустить нельзя, так что звонки между мобильными сетями могут не соединяться.
- В Supabase бесплатно 1 ГБ под файлы и 500 МБ под базу. Если под файлы нужно больше, подключите S3-хранилище (следующий раздел).


## Больше места под файлы: S3-хранилище

Музыка и клипы быстро съедают бесплатный гигабайт Supabase. Файлы можно вынести в любое хранилище с протоколом S3: Cloud.ru Object Storage (15 ГБ бесплатно бессрочно), Yandex Object Storage, Backblaze B2, свой MinIO. База при этом остаётся там же, где была.

Переменные:

| Переменная | Пример | Что это |
|---|---|---|
| `S3_ENDPOINT` | `https://s3.cloud.ru` | адрес хранилища |
| `S3_REGION` | `ru-central-1` | регион |
| `S3_BUCKET` | `nudist-files` | бакет (закрытый, без публичного доступа) |
| `S3_KEY_ID` | `<tenant_id>:<key_id>` | идентификатор ключа; в Cloud.ru перед ним через двоеточие пишется Tenant ID хранилища |
| `S3_SECRET` | | секрет ключа |
| `S3_MAX_GB` | `14` | свой потолок: когда он достигнут, сервер отказывает в загрузке (код 507), и вы не выходите за бесплатный объём |

Для Cloud.ru создайте сервисный аккаунт с ролями `s3e.editor` и `s3e.viewer` (обе нужны: первая пишет, вторая читает) и ключ доступа к нему. Личный ключ учётной записи на сервер класть не стоит: у него права на всё облако.

Как это работает:

- новый файл сохраняется на диск сервера и сразу отправляется в бакет, в папку `uploads/`;
- диск сервера служит кешем размером `CACHE_MB`; давно не открывавшиеся файлы с него удаляются и при следующем обращении скачиваются заново;
- старые файлы из Supabase продолжают открываться и при первом обращении переезжают в S3;
- занятое место видно в админке и в `/api/health` (поле `files`).

## Android

В папке `android/` — приложение-оболочка: один экран с WebView, который открывает сервер «Нудиста». Готовая сборка — `android/nudist-android.apk` (версия 1.4, Android 8.0+, 37 КБ), в неё вшит адрес `https://nudist.onrender.com`. Сервер раздаёт её же по адресу `/nudist.apk`.

Кнопка «Назад» снимает экраны по одному: меню → окно → панель → чат → чат, из которого перешли → сервер → архив → папка, и только потом сворачивает приложение. Логика живёт в `public/js/back.js` и работает и в браузере телефона, и в оболочке.

- Открывает вшитый адрес сразу. Если адрес не вшит, спрашивает его при первом запуске.
- Сменить адрес: долгое нажатие на значок → «Сменить сервер».
- Пока сервер просыпается, показывает заставку; при ошибке — экран с кнопкой «Попробовать снова».
- Умеет: вход и переписку, выбор файлов, запрос микрофона и камеры, скачивание файлов через системные «Загрузки», внешние ссылки открывает в браузере.
- С версии 1.3 показывает уведомления в шторке телефона, когда приложение свёрнуто или закрыто (см. «Уведомления в приложении для Android»).
- С версии 1.4 принимает аудио из других программ: «Поделиться» → «В музыку Нудиста» — файл загружается в «Мою музыку» (до 10 файлов за раз, до 100 МБ каждый). Вставки с других сайтов (плеер Яндекс Музыки) открываются внутри приложения.
- Какая сборка последняя, написано в `public/apk.json`; у кого версия старее, при входе видит окно «Вышло обновление».
- Не умеет: звонки в фоне (о входящем звонке придёт уведомление, но экран вызова сам не откроется), сохранение файлов, которые создаются прямо в браузере (экспорт чата, мем из генератора).
- По `http://` работают чаты, но не микрофон, камера и секретные чаты — им нужен `https://`.

Пересобрать: `SERVER_URL=https://ваш.адрес ANDROID_SDK=/путь/к/sdk ./android/build.sh` (JDK 11 или 17, `platforms;android-34`, `build-tools;34.0.0`, без Gradle). Без `SERVER_URL` получится сборка с экраном настройки. Подпись — ключом `android/nudist.keystore`; он тестовый и в репозиторий не попадает. Обновление ставится поверх старой версии, только если подписано тем же ключом.

## Честно о границах

Это один процесс Node.js с базой в JSON-файле. Он рассчитан на компанию друзей, а не на миллион пользователей.

| Из ТЗ | Как сделано |
|---|---|
| SMS-коды | шлюза нет: код показывается на экране и пишется в лог сервера |
| Push через FCM/APNs | нет; вместо них Web Push в браузерах и собственная фоновая служба в приложении для Android |
| Приложения Android / iOS / Desktop | Android — оболочка над веб-версией (см. выше); версия 1.0 запускалась на телефоне, 1.1, 1.2 и 1.3 на устройстве не проверялись; iOS и Desktop — нет, есть адаптивная веб-версия |
| Групповые звонки до 1000 человек, SFU | WebRTC mesh, до 12 участников в комнате; TURN ставит `deploy/install.sh` (или задайте `TURN_HOST`/`ICE_SERVERS`) |
| Signal Protocol | секретные чаты шифруются ECDH P-256 + AES-256-GCM в браузере; двойного храповика нет, ключ привязан к устройству |
| E2EE обычных личных чатов | нет, шифруются только секретные чаты |
| Passkeys | нет; второй фактор — TOTP и резервные коды |
| Автоперевод | нет настоящего перевода; есть транслит и «олбанский» |
| Расшифровка голосовых | через распознавание речи браузера во время записи (где оно есть) |
| «Войти через Нудист» (OAuth), импорт из WhatsApp/Telegram | нет |
| Kafka, кластер | нет и не нужны одному процессу |
| Оплата | «листики» — игрушечная валюта, настоящих денег нет |
| Блокировка скриншотов | браузер этого не умеет; в секретных чатах экран прикрывается при потере фокуса |
| Фон и размытие в видеозвонках | эффекты камеры действуют на весь кадр: размытие, пиксельная «цензура», фиговый листок; человека от фона не отделяют |

Перед тем как пускать в интернет: поставьте за HTTPS-прокси, задайте TURN, делайте копии `DATA_DIR`.

## Вес и скорость

- Текстовые файлы отдаются в brotli (или gzip). Первая загрузка интерфейса: около 190 КБ кода и стилей плюс шрифты.
- Словарь эмодзи (210 КБ) подгружается, только когда открывают панель смайликов.
- Service worker (`/sw.js`, собирается сервером) сохраняет оболочку на устройстве: со второго захода приложение открывается с диска и стартует даже без сети. После выкладки новой версии появляется плашка «Вышла новая версия». Выключить: переменная `NO_SW=1`.
- Сайт ставится как приложение (PWA): меню → «Установить как приложение». На iPhone: Safari → «Поделиться» → «На экран „Домой“».

## Сколько людей выдержит

Архитектура прежняя: один процесс Node, вся база в памяти, снимок в файл и в Supabase. Убраны места, где работа росла как квадрат числа пользователей (рассылка «в сети» всем подряд, пересчёт участников на каждое сообщение, хеш пароля на главном потоке, сохранение базы каждые полсекунды при любом размере).

Замер на одной машине (`node deploy/load.js 10000 30 3 http://localhost:3000`, каждый пользователь держит WebSocket и пишет соседу):

| Одновременно в сети | Сообщений в секунду | Доставка, p95 | Память процесса |
| --- | --- | --- | --- |
| 3 000 | 300 | 50 мс | 230 МБ |
| 10 000 | 500 | 150 мс | 320 МБ |

До правок 3 000 регистраций не укладывались в 5 минут, после правок 10 000 проходят за 3 минуты.

Чего это **не** даёт: миллионов. Пределы такие:
- бесплатный Render: 512 МБ памяти и доля ядра. Реалистично до 1–3 тысяч человек одновременно;
- снимок базы целиком: на пользователя уходит около 2 КБ плюс переписка. После 50–100 тысяч аккаунтов сохранение начнёт заметно тормозить, а снимок перестанет помещаться в бесплатный Supabase;
- для сотен тысяч и миллионов нужны настоящая база (PostgreSQL с записью по строкам), несколько серверов за балансировщиком с общей шиной событий, хранилище файлов с CDN и платный хостинг.

## Перенос записей из Telegram и подборки редакции

`scripts/tg-import.js` переносит записи из своего открытого Telegram-канала в «Ленту», а видео ещё и в «Клипы»: с исходными датами, фото, видео, кружками и голосовыми. Запуск: `TG=канал SITE=https://сайт TOKEN=<токен сессии> STATE=./tg-state.json node scripts/tg-import.js` (нужен `ffmpeg`). Повторный запуск продолжает с места остановки. Не переносятся пересланные записи, опросы, стикеры, музыка и файлы (на веб-странице канала на них нет ссылок) и видео, которые Telegram не отдаёт в браузер из-за размера. Видео пережимается, в ленте и в клипах стоит один и тот же файл.

Переменные сервера:

- `IMPORTERS` — id аккаунтов через запятую, которым можно публиковать записи, клипы и треки с любой датой, без дневных лимитов, с видео и голосовыми в записях. Дата в будущем работает как отложенная публикация: запись скрыта и сама появляется, когда приходит её время.
- `ROBOTS` — id аккаунтов редакции с автоматическими подборками; рядом с их именем показывается значок «Бот». Их истории видны всем, а на их открытые каналы новые люди подписываются сразу при регистрации, чтобы список чатов не был пустым.

Адрес `https://<сайт>/start` (то же самое по `/download`) — страница, которую удобно давать в рекламе: коротко о мессенджере и одна кнопка «Скачать APK».

## Уведомления при закрытом приложении

Меню ☰ → «Уведомления» → «Включить уведомления» (на каждом устройстве отдельно; там же кнопки «Проверить» и «Выключить»). Используется Web Push: работает в Chrome, Яндекс Браузере, Edge, Firefox и в приложении, установленном из браузера («Установить приложение»), на iPhone — только для сайта, добавленного на экран «Домой». **В APK на WebView механизма push нет**, там окно честно это пишет.

Что присылается, когда у человека нет ни одного открытого соединения: личные сообщения, сообщения в группах, анонимные вопросы, входящие и пропущенные звонки. Каналы и серверы — только упоминания; чаты с выключенным звуком и заблокированные люди молчат; секретные чаты приходят без текста. Не больше 20 уведомлений в минуту на человека.

Сторонних библиотек нет: подпись VAPID и шифрование `aes128gcm` сделаны на встроенном `crypto` (`server/push.js`), обработчики `push` и `notificationclick` добавляются в сервис-воркер в `server/index.js`, окно настроек — в `public/js/growth.js`. Ключи сервера создаются при первом обращении и хранятся в базе; свои можно задать переменными `VAPID_PUBLIC`, `VAPID_PRIVATE` (base64url) и `VAPID_SUBJECT` (`mailto:…`). Если ключ сменить, всем придётся включить уведомления заново. Сервер шлёт запросы только известным службам доставки (Google, Mozilla, Apple, Microsoft).

### Уведомления в приложении для Android

В APK сервисов Google нет, поэтому с версии 1.3 приложение ждёт сообщения само. Как это устроено:

- После входа страница зовёт `window.NudistApp.sync()`. Приложение читает ключ сеанса из хранилища главной страницы (сам ключ через мост не передаётся, поэтому вставленное мини-приложение не может его подменить) и запускает фоновую службу `PushService`.
- Служба держит долгий запрос `GET /api/notify?since=N&tz=<смещение в минутах>` с заголовком `Authorization: Bearer`. Сервер отвечает сразу, как только для человека появилось событие, или пустым ответом через 40 секунд. Лента живёт в памяти сервера и только у тех, чей телефон спрашивал в последние 5 минут.
- Пока приложение на экране, служба молчит. Когда оно свёрнуто, показывает уведомление; сообщения одного чата складываются в одно. Нажатие открывает этот чат.
- Учитываются настройки из «Настройки → Уведомления»: личные и группы, «Показывать текст сообщения», тихие часы (по времени телефона), выключенный звук чата. Каналы и серверы присылают только упоминания.
- Android требует, чтобы у такой службы была постоянная строка в шторке («Нудист на связи»). Она тихая, её можно скрыть в настройках уведомлений приложения (канал «Связь с сервером»).
- Меню ☰ → «Уведомления»: выключатель, просьба разрешить уведомления (Android 13+), просьба снять ограничение батареи и кнопка «Проверить» (уведомление приходит через 10 секунд, приложение нужно свернуть).

Ограничения: на спящем телефоне с включённой экономией батареи уведомления могут опаздывать на минуты; на Xiaomi, Huawei, Honor и Samsung приложению нужно дополнительно разрешить автозапуск, иначе система закроет службу. Если сервер перезапустился или телефон был без сети дольше 5 минут, пропущенные за это время сообщения в шторку не попадут (в самом приложении они на месте). На настоящем телефоне версия 1.3 не проверялась.

## Лента

Вкладка «Лента» (первая на экране с музыкой и клипами, кнопка со списком в левой колонке, пункт в меню ☰, адрес `…/#hub=feed`). Запись: текст до 2000 знаков и до четырёх картинок. Лайки, комментарии, удаление своих записей, подписка на автора. Вкладки: «Для вас» (рекомендации), «Новое» (записи всех людей по времени плюс свежие записи каналов, на которые человек подписан), «Подписки», «Мои». Заблокированные люди не видят записи друг друга и не могут комментировать. Пределы: 30 записей и 300 комментариев в день. Модераторы могут удалить любую запись. Код: `server/feed.js`, `public/js/feed.js`, стили в `public/css/hub.css`.

### Рекомендации, просмотры и живое обновление

- **«Для вас».** Нейросетей нет: каждая запись получает оценку, лента сортируется по ней. Учитываются свежесть (старое опускается, но не пропадает), отклик (лайки и комментарии), интерес человека к автору (подписка, его лайки и комментарии под записями этого автора), наличие картинки или видео. Уже просмотренное уходит в хвост. Записи одного автора разводятся штрафом, чтобы он не занял всю ленту. Небольшой случайный разброс меняется раз в день. Клипы упорядочены так же: сначала непросмотренное. Формулы — в `server/feed.js` (`recommend`) и `server/hub.js` (`clipRank`).
- **Бесконечная лента.** Кнопки «Показать ещё» нет: следующая порция подгружается сама, когда до конца остаётся пара экранов.
- **Живое обновление.** Раз в 2,5 минуты и при возвращении на вкладку приложение спрашивает сервер, что нового. Если человек наверху, новые записи просто появляются; если читает ниже, сверху возникает кнопка «Новые записи: N». Заодно обновляются счётчики лайков, комментариев и просмотров и исчезают удалённые записи.
- **Кто посмотрел.** Автор видит список людей, которые посмотрели его запись (кнопка с глазом), клип (глаз справа) или послушали его трек (меню трека → «Кто слушал»); в историях это было и раньше. Список виден только автору, хранятся последние 300 человек на каждую запись, общий счётчик не обрезается. Запись считается просмотренной, если секунду провисела на экране хотя бы наполовину.

## Звонки, когда напрямую не соединяется

Звонки идут напрямую между устройствами (WebRTC). Без своего TURN-сервера прямое соединение часто не устанавливается: мобильный интернет, VPN, строгий NAT. Тогда через 5 секунд (или сразу после ошибки) звук автоматически идёт **через сервер**: микрофон → 16 кГц моно, μ-law (около 16 КБ/с в каждую сторону) → двоичные кадры по тому же веб-сокету → собеседник. В плитке участника появляется подпись «через сервер». Если прямое соединение всё же поднимется, запасной путь отключается сам.

Ограничения запасного пути: только звук (видео, демонстрация экрана и эфиры по-прежнему требуют прямого соединения или TURN), задержка около 0,3 секунды, качество «телефонное». Полноценное решение — свой TURN: переменные `TURN_HOST` и `TURN_SECRET` (coturn уже есть в `docker-compose.yml`). Код: `public/js/rtc.js` (раздел «звук через сервер»), `server/guild.js` (`audio`).

## Что добавлено для роста

- **Приглашения.** Меню → «Позвать друзей»: личная ссылка `…/?ref=username`, QR, кнопка «Поделиться», счётчик и доска почёта. Новичок по ссылке сразу попадает в контакты к позвавшему, обоим по 50 🍃 (не больше 20 оплаченных приглашений в день).
- **«Голая правда» — анонимные вопросы.** Меню → «Голая правда»: личная ссылка `…/q/username`, которую выкладывают в истории и в профиль любой соцсети. Гость задаёт вопрос без регистрации (до 500 знаков, ссылки вырезаются), вопрос приходит в чат с ботом `@pravda`. Кнопка «Картинка для истории» рисует вертикальную карточку 1080×1920. На странице гостя — «Получить свою ссылку»: регистрация по приглашению хозяина ссылки (обоим по 50 🍃). Имя, номер и адрес отправителя не сохраняются; хранится только обезличенный отпечаток, чтобы можно было заблокировать автора вопроса, не зная, кто он. Лимиты: 6 вопросов за 10 минут и 25 в час с одного адреса, 120 в час одному получателю. Приём вопросов выключается там же. Код: `server/ask.js`, `public/ask.html`, `public/js/ask.js`, `public/js/growth.js`.
- **Красивая карточка ссылки** в других мессенджерах и соцсетях (Open Graph, `og.png`).
- **Серия переписки** («огонёк»): сколько дней подряд оба пишут друг другу; день считается по Москве, показывается с двух дней.
- **Одноразовые фото и видео** в личных чатах: открываются один раз, потом файл стирается с сервера; переслать нельзя. От снимка экрана в браузере защититься невозможно.

Чего по сравнению с Telegram, WhatsApp, MAX и VK всё ещё нет: встроенного ИИ-помощника, переводов денег, прямых эфиров, синхронизации телефонной книги, расшифровки голосовых, сквозного шифрования во всех чатах, приложений для iOS и компьютера (вместо них PWA).

## Музыка, клипы, эфиры, приложения, поддержка

Кнопки слева под списком серверов (нота, плёнка, антенна, плитки) открывают общий экран с вкладками. Код: `server/hub.js`, `public/js/hub.js`, `public/css/hub.css`.

- **Музыка.** «Загрузить» — свои mp3 (а также m4a, ogg, wav, flac). Трек по умолчанию личный; в меню трека его можно выложить в «Общую волну», откуда другие добавляют его к себе. Встроенный плеер: очередь, следующий/предыдущий, повтор, перемешивание, перемотка; играет и при переходе в чаты. Трек можно отправить в открытый чат.
  Кроме своих файлов есть музыка из сети (`server/tunes.js`) — к себе её сервер не копирует, звук идёт прямо с источника:
  - «Каталог» — поиск по музыке со свободными лицензиями (Jamendo через открытый API Openverse); у каждого трека автор, лицензия и ссылка на страницу автора. Без ключа Openverse даёт 200 запросов в сутки, поэтому ответы хранятся в памяти 12 часов.
  - «Радио» — станции из открытого справочника Radio Browser (только https-потоки mp3/aac/ogg).
  - «Из Яндекса» — ссылка на трек, альбом или плейлист Яндекс Музыки превращается в официальный встраиваемый плеер Яндекса. Что играть целиком, решает Яндекс; файлы не скачиваются.
  - Плюс у трека или станции добавляет запись в «Мою музыку». Адреса берутся только из ответов источников, подсунуть свой нельзя.
- **Клипы.** Вертикальная лента с прокруткой по одному видео, до 3 минут (mp4, webm, mov). Лайки, комментарии, счётчик просмотров (один на человека), звук одной кнопкой.
- **Эфиры.** Камера или экран, чат эфира, сердечки, счётчик зрителей. Видео идёт напрямую от ведущего каждому зрителю (WebRTC), сервер их только знакомит. Отсюда границы: до `LIVE_MAX_VIEWERS` зрителей, качество зависит от интернета ведущего, записи нет, без TURN-сервера часть мобильных сетей не соединится. Для эфиров на сотни зрителей нужен медиасервер (SFU) на отдельной машине.
- **Приложения.** См. раздел Mini Apps выше.
- **Поддержка.** Вкладка «Поддержка»: частые вопросы и кнопка «Написать». Чат ведёт бот `@support`: на частые вопросы отвечает сам, остальное становится обращением. Модераторы и выше видят очередь на той же вкладке, отвечают от имени поддержки и закрывают обращения. `/operator` в чате сразу зовёт человека.

Модерации по авторским правам нет: за загруженную музыку и видео отвечает тот, кто их загрузил. Модератор может удалить любой трек и клип и остановить эфир.

## Листики: откуда берутся

Листики нарочно добываются медленно, иначе Премиум (500 🍃) и буст (200 🍃) ничего не стоят.

| Источник | Сколько |
|---|---|
| Регистрация | 500 🍃 один раз (`LEAF_START`) |
| Игры «2048» и «Сапёр» | 2048: за плитки 128–2048 от 2 до 30 🍃, до 60 в день; Сапёр: 10 🍃 за победу, до 50 в день |
| Ежедневный бонус | 10–20 🍃 раз в сутки |
| «Листопад» | 1 🍃 за каждые 10 тапов, не больше 150 🍃 в сутки |
| Приглашённый друг | по 50 🍃 обоим; пригласившему платят не больше чем за 5 человек в сутки |

Сервер принимает не больше 15 тапов в секунду с одного аккаунта, так что скрипт-автокликер получит столько же, сколько живой палец. Числа меняются переменными `LEAF_*` (таблица выше), баланс конкретного человека — в админке.
